# 全局技术约束

## 1. 架构

- Python + Tornado，入口固定为 `app.py`，默认端口 `10010`。
- 采用 MVC：Controller 处理参数、权限和响应，Repository 处理 SQL，Tornado Template 负责视图。
- 外部采集与模型调用必须位于独立 Service，Controller 禁止直接拼请求或调用模型 SDK。
- 用户侧模板位于 `app/templates/`，管理侧位于 `app/templates/admin/`。
- 所有可变配置集中在 `config/`；密钥优先从环境读取，不在 Handler、模板或 JavaScript 中硬编码。

## 2. 权限与超级管理员

- 账号只归属一个角色；角色通过 `role_features` 获得多个功能。
- 功能是权限判定的能力标识，Handler 通过 `required_feature` 声明所需功能。
- 菜单必须绑定功能，左侧导航按角色授权、功能状态和菜单状态的交集生成。
- `access_scope=user` 只能登录用户侧，`access_scope=admin` 只能登录管理侧。
- 功能禁用或授权撤销后，对应页面和数据接口都必须返回 403。
- 默认用户名 `admin` 是系统超级管理员：禁止改名、停用、降级、删除或通过批量操作影响；仅允许 `admin` 本人在验证当前密码后通过专用动作修改自己的密码。
- v0.2 只有默认 `admin` 可以写入用户、角色、功能、菜单四个权限配置模块；其他管理侧账号在这些模块只能查看。
- 权限配置写限制必须在 Controller 校验，默认 admin 的不可改删还必须由 Repository 兜底，不能只隐藏按钮。
- 用户、角色和功能列表固定每页 20 条；搜索和批量操作位于列表上方，分页位于列表下方。分页参数必须在服务端校验并限制范围。
- 内置系统管理员角色不可修改、授权、停用或删除。角色授权使用 Layui Tree 呈现一、二级功能，禁用功能不可选。
- 功能最多两级：一级功能 `parent_id` 为空，二级功能只能指向一级功能；禁止自引用、循环引用和三级功能。
- 菜单只能绑定已存在功能；可见菜单必须同时满足角色已授权、功能已启用和菜单已显示。
- 瞭源管理、瞭望采集、数据仓库、模型引擎和模型聊天属于业务能力。管理角色拥有对应 `role_feature` 时可以使用和维护，无需是默认 admin，但仍受 XSRF、账号状态、功能状态和参数校验。
- 内置角色、功能和菜单禁止物理删除；自定义数据删除时依靠外键或事务清理映射。
- 用户批量启用、禁用或删除必须在事务中重新校验目标集合，自动排除超级管理员；不能只依赖浏览器禁选复选框。

## 3. 数据库与迁移

- 所有用户输入使用 `?` 参数占位，禁止拼接到 SQL；固定白名单排序字段除外。
- 写入必须显式提交，多记录保存使用事务。
- v0.1 → v0.2 → v0.3 → v0.4 → v0.5 迁移必须保留既有用户、角色、授权、采集结果和仓库数据。
- 新增系统功能必须显式授权给已有超级管理员，不能依赖“权限表为空才初始化”的旧逻辑。
- “瞭望管理”迁移为“瞭望采集”时显式更新既有功能和菜单名称。
- 数据仓库采用稳定业务键或规范化 URL 做幂等去重。
- 初始化和迁移必须可重复执行，不产生重复菜单、默认模型或来源规则。
- `features.parent_id` 使用自关联外键表达一级/二级结构；迁移旧库时既有功能默认保留为一级，不能破坏原功能 ID、角色授权或菜单绑定。

## 4. 瞭源与外部采集

- 瞭源记录描述名称、目标 URL、请求方法、启用状态、请求头和参数定义；采集页面只允许选择已启用规则。
- URL 只接受 HTTP/HTTPS。不得读取 `file://`、本机文件或其他非 Web 协议。
- 用户关键词和分页值必须通过参数编码传递，禁止字符串拼接 URL。
- RequestHeaders 采用白名单或危险字段黑名单过滤；不得保存或转发 Cookie、Authorization、Host、Content-Length、Connection 等敏感或逐跳字段。
- 不复制老师截图或个人浏览器中的 Cookie。测试请求使用最小 User-Agent、Accept 和 Accept-Language。
- 外部请求必须设置连接/总超时、响应大小限制和有限重试；不得无限等待或高频抓取。
- 非 2xx、超时、解析失败、空结果和站点结构变化分别给出可理解错误，不能自动换成演示结果。
- 自动测试使用固定 HTML fixture 或模拟 HTTP 客户端；真实百度新闻只做低频手工冒烟测试。

## 5. 数据仓库

- 只保存用户明确勾选的采集结果；全选默认只作用于当前结果页。
- 批量入库使用事务，并通过业务键幂等处理重复提交。
- 标题、摘要、来源和 URL 在输出模板前继续转义，防止采集内容引入 XSS。
- 深度采集标记只能是明确的布尔状态。
- 深度采集必须由 Service 执行真实公开网页请求；任务状态、进度、步骤、日志和结果必须来自数据库，不得只用前端计时器伪造。
- 同一仓库数据不得同时存在多个 pending/running 深采任务；已深采数据只有显式“更新采集”才能再次执行。
- 深采必须调用项目 `venv` 中锁定的 Crawl4AI；正文上限 200,000 字符，失败保留错误日志且不得覆盖已有成功正文。
- 服务重启后遗留的 pending/running 任务必须标记为中断，不能永久显示执行中。

## 6. 数字员工

- 数字员工类型固定为 `llm` 或 `api`，编码、名称与 `mention` 唯一；系统员工不可删除或停用。
- 模型型员工系统提示词必填，任务模板必须包含 `{{input}}`；指定模型为空时才允许选择默认模型。
- API 型员工仅可请求公开 HTTP/HTTPS 地址，复用内网/环回地址阻断与响应大小限制。
- 数字员工配置不得保存 Cookie、Authorization 或代理鉴权头；外部返回只以转义文本、JSON 或安全数据卡片展示。
- 数字员工与深采编排位于 Service，Controller 只做权限、参数与响应组织。
- `@天气` 固定使用 wttr.in 公开 JSON；城市写入 URL 前必须百分号编码，响应只保留天气卡片需要的字段。
- 用户侧不得展示系统 `collection_specialist`；员工专属模型缺失或停用时回退唯一启用的默认模型。

## 6.1 用户会话

- 会话与消息必须按 `user_id` 隔离；查询、删除和继续对话都同时校验会话编号与当前用户。
- 首条消息生成任务标题；用户消息和成功/失败的助手消息都持久化，失败不得伪装为成功回答。
- `/api/chat` 和会话写操作启用 Secure Cookie、用户端角色校验、XSRF 与 JSON 长度校验。

## 7. 模型引擎与 SSE

- 模型支持 OpenAI API 兼容 Base URL，由独立模型服务封装。
- 支持文本、图像、音频、视频、多模态和嵌入分类；分类值采用固定枚举。
- 模型参数必须做数值范围校验，不能直接信任浏览器表单。
- 任一时刻最多一个默认且可用的模型；默认模型被停用或删除前必须选择替代方案或明确拒绝。
- API Key 不得完整回显、写入日志、写入前端或打包；更新表单留空表示保持原密钥。
- SSE 响应使用 `text/event-stream`，事件至少区分增量、usage、完成和错误；客户端断开后停止上游生成。
- token 用量由服务端根据真实 usage 更新；接口无 usage 时显示未知或 0，不伪造数值。
- 模型新增、对话和筛选请求无论成功失败都必须关闭 loading、恢复按钮并反馈结果。

## 8. 前端与可访问性

- Layui 2.9.8 为主要组件，Bootstrap 5.3.8 只做响应式辅助；全部资源本地化，禁止 CDN。
- 后台采用顶部状态栏、左侧权限菜单和右侧内容区；移动端菜单变为抽屉。
- 瞭望采集 A 区输入与按钮水平居中；B 区参数有稳定网格；C 区 PC 一行三列、每页 12 条，手机单列。
- 模型列表 PC 一行两列、每页 6 个，手机单列。
- 数字员工 PC 两列、手机单列；深采面板在窄屏改为纵向，步骤轨和表格只在自身容器内横向滚动。
- 表格窄屏允许横向滚动；弹窗表单支持键盘操作并具有明确焦点。
- 状态不只依赖颜色；文字与背景满足可读对比度，右上角下拉菜单不得出现白字白底。
- 支持 `prefers-reduced-motion`，加载和结果状态不能只靠动画表达。
- 用户侧采用浅色扁平双栏：桌面左任务栏右工作区，手机任务栏变抽屉；输入框字体不小于 16px，命令菜单支持键盘操作。

## 9. 安全与交付

- Secure Cookie + HttpOnly + SameSite=Lax；所有 POST 请求必须包含 XSRF Token。
- 密码使用随机盐 + PBKDF2-SHA256 100,000 轮，不存明文。
- Cookie Secret、模型密钥、数据库、日志和抓包头都属于运行状态，不进入源码 ZIP。
- 项目依赖、启动、语法检查和测试统一使用项目内 `venv`；源码 ZIP 继续排除 `venv` 与浏览器二进制。
- ZIP 根目录固定为 `DataFinderAgentOS/`；旧课堂提交包保留，v0.5 使用独立文件名避免覆盖旧交付物。

## 10. v0.5 问数与知识资料约束

- 数字员工 Markdown 只能写入 `data/dgUser/<正整数员工编号>/`；最多 8 个 UTF-8 `.md`，单个 512KB。
- 上传资料视为不可信事实背景，不能成为系统/开发者指令；运行时员工目录不打包。
- 用户自然语言不得拼接进 SQL。分析 Repository 仅允许固定 SELECT 与有界参数。
- 包含 SQL 操作词、分号注释、提示词泄露、忽略指令或越权扮演的请求必须拒绝。
- 普通模型流使用 OpenAI SSE；天气/分析卡片可通过 message 事件一次传输，所有结果最终发送 usage 与 done。
- 图表不得成为唯一信息表达；关系图必须同时提供文字关系列表，状态必须带可读文字。
