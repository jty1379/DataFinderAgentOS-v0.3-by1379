# 项目角色与产品定位

## 系统定位

“瞭望与问数系统（DataFinderAgentOS）”是面向政务场景的 B/S 数据采集、治理和智能问数系统。系统包含用户侧和管理侧：用户通过对话体验问数能力，管理侧维护权限、瞭源、采集数据、数据仓库和 OpenAI API 兼容模型。

## 人员角色

- 普通用户（`user`）：只能登录用户侧，使用被授权的用户门户能力。
- 默认超级管理员（用户名 `admin`）：只能登录管理侧，是 v0.2 唯一允许写入用户、角色、功能、菜单四个权限配置模块的账号；该账号本身禁止改名、停用、降级和删除，只能由本人验证当前密码后修改自己的密码。
- 其他管理侧角色：是否能看到模块由角色—功能授权决定；在用户、角色、功能、菜单四个权限配置模块中只能查看，不能新增、修改、授权、排序、停用、重置密码或删除。
- 业务管理角色：拥有对应 `role_feature` 时，可以使用和维护瞭源管理、瞭望采集、数据仓库、数字员工和模型引擎；这些操作仍必须通过 XSRF、账号状态、功能授权和服务端参数校验。
- 自定义用户侧角色：只能进入用户侧，通过功能授权决定可见入口。

菜单可见不等于有权访问。所有页面、表单、采集接口、模型接口和 SSE 地址都必须由 Handler 在服务端重新验证账号状态、端侧和功能授权。超级管理员独占的是权限配置，不是所有业务操作。

## 系统职责

- Controller：接收和校验请求、执行权限判断、组织响应，不直接操作 SQL 或拼装外部服务协议。
- Repository：维护 SQLite 查询、事务、去重和数据关系。
- 采集服务：根据启用的瞭源规则构造安全的外部请求，处理超时、编码、解析和规范化。
- 模型服务：封装 OpenAI API 兼容调用和 SSE 数据转换，选择默认模型并记录 token 用量。
- 数字员工服务：统一调度模型型/API 型员工，处理提示词、参数模板、公开地址校验和后台预览。
- 深采服务：由“采集专员”强制调用 Crawl4AI 浏览器获取公开网页、解析详细正文，并将任务进度、日志和结果持久化。
- 用户会话服务：依据当前用户隔离会话和消息，组织默认模型或数字员工调用，不允许越权读取他人历史。
- View：展示真实状态；未完成、失败或没有数据时必须明确说明，不能用演示数据冒充真实采集或真实模型回答。

## v0.3 模块边界

管理侧真实模块包括用户、角色、功能、菜单、瞭源管理、瞭望采集、数据仓库、数字员工和模型引擎。深采由系统“采集专员”通过 Crawl4AI 执行并持久化。用户侧已实现注册登录、任务历史、OpenAI SSE、`@数字员工`、真实仓库统计、关系图谱与分析报告；大屏和复杂数据治理仍属于后续版本。

## v0.3 新增服务职责

- 员工知识资料服务：校验和隔离 Markdown 上传，只向对应员工 Prompt 提供有界事实背景。
- 问数编排服务：统一处理会话、模型、员工、安全意图、消息持久化、耗时和 token 元数据。
- 数据分析 Repository：只提供固定只读查询，不接受 SQL 字符串或字段名输入。
- 意图服务：拒绝 SQL/Prompt 注入，按概览、分布、趋势、深采、关系、图谱和报告分派真实查询。

## 权限数据关系

- 每个用户必须且只能绑定一个角色。
- 一个角色可以绑定多个功能，一个功能也可以授权给多个角色，映射由 `role_features` 保存。
- 功能按一、二级组织；角色授权树展示这一层级，但权限判断始终使用功能编码。
- 一个菜单只能绑定一个功能。左侧菜单不是独立授权源，而是角色授权、功能启用状态和菜单显示状态的可视化结果。
- 内置系统管理员角色与默认 `admin` 账号是两类保护对象：角色不可编辑或删除；账号除本人改密外不可修改、停用或删除。
