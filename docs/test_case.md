# 测试用例

自动测试命令：

```powershell
.\venv\Scripts\python.exe -m unittest discover -s test -v
```

自动测试使用临时 SQLite 数据库。外部采集和模型服务必须 mock，不依赖真实百度新闻、真实 API Key 或模型余额。

## 1. 初始化与迁移

1. 空数据库初始化生成 v0.2 全部表、索引、角色、功能、菜单和 admin。
2. 重复初始化无重复默认数据，admin 密码不被重置。
3. 由 v0.1 表结构迁移后保留用户、角色和原授权。
4. 旧“瞭望管理”迁移成“瞭望采集”。
5. 新增系统功能自动授予已有 admin，不自动授予自定义角色。
6. `schema_migrations` 记录版本且迁移可重复执行。

## 2. 认证、权限和超级管理员

1. 普通用户不能进入 `/admin/`，管理员不能进入用户侧。
2. 未登录访问管理地址跳转 `/admin/login`。
3. 缺少 XSRF Token 的 POST 返回 403，SQL 注入式输入不能绕过认证。
4. 创建 `useradmin` 管理侧角色并授予 `user_management`，再创建 `useradmin / admin888`；该账号能登录后台并打开用户管理页。
5. `useradmin` 对用户、角色、功能、菜单的写请求均返回 403，且目标数据不变；这覆盖任务 2.1 与 2.2 的越权回归。
6. 默认 admin 不能被改名、停用、降级、删除或通过批量启停/删除影响。
7. `admin` 本人输入错误旧密码不能改密；输入正确旧密码可以修改自己的密码；其他账号不能调用该动作。
8. admin 专用改密表单不包含用户名、角色、状态等可编辑字段；通用用户编辑动作对 admin 始终失败。
9. 内置系统管理员角色不能修改、停用、重新授权或删除；普通自定义角色可正常维护。
10. 当前账号和最后一个可用管理员保护继续有效。
11. 撤销业务模块授权或停用功能后，页面、POST、数据接口和 SSE 均返回 403。
12. 拥有对应 `role_feature` 的非超级管理角色可以维护瞭源、发起瞭望采集、入仓、维护模型和发起模型聊天。

3. 用户搜索、角色筛选、状态筛选与分页组合后总数和列表一致。
4. 新建 21 个以上角色后按每页 20 条分页；角色页沿用上、中、下三段布局。
5. 角色授权区由本地 Layui `tree.render` 初始化；一级、二级功能树结构正确，禁用节点不可勾选。
6. 系统管理员角色在页面不出现编辑、授权、停用和删除入口，伪造 POST 仍被 Repository/Handler 拒绝。
7. 新建一级功能及其二级功能成功；二级功能不能再成为其他功能的父级，不能把功能设为自身或后代的子级。
8. 功能列表固定每页 20 条并展示图标、名称、层级、路由和状态；一级/二级关系具有文字或缩进表达，不能只靠颜色。
9. 禁用已授权功能后，角色权限判定立即失败，菜单预览和真实左侧菜单均不再显示；重新启用后按原映射恢复。
10. 菜单排序后顺序持久化；按角色预览仅展示该角色已授权且功能启用、菜单显示的项目。
11. 用户与角色是一对一关系；删除仍有关联用户的自定义角色失败并给出原因。

## 4. 瞭源管理

1. 瞭源和规则支持新增、修改、删除、启停、搜索和分页。
2. 重复编码、空名称、非法方法、非 HTTP/HTTPS URL 和错误参数配置被拒绝。
3. 规则参数正确表达关键词、页码、步长和固定参数。
4. 禁用瞭源或规则不能用于采集。
5. Cookie、Authorization、Host、Content-Length 和 Connection 不得保存或转发。
6. 列表及编辑页不回显敏感请求头。
7. 删除被采集记录引用的规则时，外键行为明确且数据仍可追溯。

## 5. 瞭望采集

1. 空关键词、无规则和禁用规则返回明确提示。
2. 中文关键词经过 URL 编码；页码和步长映射正确。
3. mock 成功响应可解析标题、摘要、来源、时间和 URL。
4. 单页结果不超过 12 条，分页边界正确。
5. 超时、非 2xx、响应过大、编码异常、空结果和 HTML 结构变化均能结束加载并显示错误。
6. 外部标题和摘要在模板中转义，脚本标签不能执行。
7. PC 一行三列，390px 宽度单列且无横向溢出。
8. 自动测试不访问百度；真实百度只做无 Cookie、低频冒烟测试并单独记录结论。

## 6. 数据仓库

1. 单选、全选当前页和未选择提示正确。
2. 批量入库只接受服务器中的采集结果 ID。
3. 同一业务键重复保存保持一条记录并返回可理解结果。
4. 批量保存发生异常时事务行为一致，不产生半批脏数据。
5. 搜索、分页、详情和删除正常。
6. 深度采集标记仅允许是/否。
7. 单条、批量和更新深采创建正确任务；已深采数据在非更新模式下跳过。
8. 深采任务依次持久化进度、步骤和日志；成功写入正文及结果，失败只写错误状态且不覆盖旧正文。
9. 深采结果详情返回最新结果，更新采集保留历史结果。
10. 采集专员不存在、停用或关闭采集能力时拒绝创建任务。

## 7. 数字员工

1. 系统采集专员首次初始化存在、可用且不可删除或停用。
2. 模型型/API 型员工支持 CRUD、启停、搜索、类型筛选和每页 8 条分页。
3. 模型型员工缺少提示词、任务模板缺少 `{{input}}`、模型不可用时明确拒绝。
4. API 型员工拒绝非 HTTP/HTTPS、内网地址、凭据 URL、Cookie 与 Authorization 请求头。
5. mock 模型预览记录真实 usage；mock API 预览解析 JSON，并分别返回 JSON/卡片模式。
6. 后台预览缺 XSRF 返回 403；无对应功能授权返回 403。
7. 当前迭代不新增用户侧数字员工路由与调用逻辑。

## 8. 模型引擎

1. 模型支持新增、修改、删除、启停、搜索和分页。
2. 文本、图像、音频、视频、多模态和嵌入分类筛选均返回正确集合。
3. 温度、top_p、上下文数和最大 token 边界校验正确。
4. API Key 不在列表、HTML、日志和错误响应中完整出现；编辑留空不清除原密钥。
5. 设置默认模型后始终只有一个默认模型。

## 10. 百度新闻冒烟测试记录

- 日期：2026-07-13。
- 关键词与分页：`四川`，`pn=0`。
- 地址：`https://www.baidu.com/s?tn=news&rtt=1&bsst=1&cl=2&word=四川&pn=0`。
- 请求条件：公开浏览器兼容请求头，无 Cookie、无 Authorization。
- 原始结果：HTTP 200，响应约 542,548 字节，未进入验证码，解析到 10 个 `news-title_*` 标题。
- 项目内链路复测：使用 `CollectorService.collect`、临时数据库默认百度规则和 12 条上限，输出 `RULES 1`、`RESULTS 10`；前三条均包含真实标题和 HTTPS URL。
- 对照：仅最小 User-Agent 的请求被重定向到 `wappass` 图形验证码。
- 结论：2026-07-13 项目内采集链路实测通过，共返回 10 条；但依赖公开请求头并受百度风控影响，不能作为稳定生产接口。自动测试继续使用 mock，运行时必须检测验证码、重定向、空结果和结构变化并显示明确错误。
- 隐私要求：测试记录和源码包不保存任何 Cookie 或私人请求头。
